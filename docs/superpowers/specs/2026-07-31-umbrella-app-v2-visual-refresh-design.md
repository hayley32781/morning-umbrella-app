# 아침 우산 알리미 v2 — 비주얼 리프레시 + 양산 기능 설계 문서

날짜: 2026-07-31

## 배경 / 목적

기존에 배포된 "아침 우산 알리미"(`index.html`, https://hayley32781.github.io/morning-umbrella-app/)는 기능이 단순하고, 배경이 브라우저 창 전체를 정적인 단색으로 채워서 "그냥 덩그러니 있는" 느낌이라는 피드백을 받았다. 이번 작업은 기존 앱의 핵심 로직(위치 감지, 강수확률 판단, Open-Meteo 연동)은 그대로 두고, 다음을 추가/개선한다:

1. 날씨별로 실제 움직이는 일러스트 애니메이션 배경
2. 화면 레이아웃을 "웹앱처럼" 중앙 고정 폭 카드로 변경
3. UV 지수 기반 "양산" 추천 기능 (우산과 탭으로 전환)
4. 습도·바람, 시간대별 미니 타임라인, 날씨별 한줄 코멘트 추가

시각적 방향은 브라우저 기반 비주얼 컴패니언으로 실제 CSS 애니메이션 목업을 여러 차례 만들어 사용자가 직접 보고 확정했다.

## 범위 (In Scope)

### 1. 레이아웃 — 카드형 고정 폭
- 화면 전체가 아니라, 중앙에 고정 폭(예: 360~400px)의 둥근 카드가 떠 있는 구조. 카드 바깥은 차분한 여백 배경.
- 카드 내부는 두 레이어로 분리:
  - **배경 애니메이션 레이어**: 날씨 캐릭터 + 파티클 애니메이션이 재생되는 층
  - **텍스트 레이어**: 결과 문구/정보가 항상 애니메이션 위에 표시되는 층 (`z-index`로 분리, 배경 패널 없이 텍스트만 얹음)
- 스태킹 순서(뒤→앞): 빗방울/눈송이 파티클 → 구름 캐릭터(파티클이 구름 뒤에서 시작해 가려졌다 나오는 효과) → 텍스트 레이어

### 2. 배경 애니메이션 — 날씨별 4가지 장면
모두 순수 CSS `@keyframes` 애니메이션으로 구현하며, 4개 장면을 모두 HTML에 미리 그려두고 현재 날씨 카테고리에 해당하는 장면만 보이도록 전환한다 (기존 `weatherCodeToCategory` 함수의 4개 카테고리 `sunny`/`cloudy`/`rainy`/`snowy`를 그대로 재사용).

- **맑음(sunny)**: 해 캐릭터가 위아래로 통통 튀고(bounce), 뭉게구름 2개가 화면을 가로질러 천천히 흘러감(drift)
- **흐림(cloudy)**: 구름 캐릭터가 좌우로 살짝 흔들림(sway). 낙하 파티클 없음
- **비(rainy)**: 구름 캐릭터(sway) + 빗방울 8~10개가 구름 근처 높이에서 시작해 구름 뒤로 가려졌다가 아래로 떨어짐(fall). 각 빗방울은 서로 다른 `left` 위치와 `animation-delay`를 가짐
- **눈(snowy)**: 구름 캐릭터(sway) + 눈송이 8~10개가 좌우로 흔들리며(drift+rotate) 천천히 떨어짐. 눈송이는 빗방울보다 느린 낙하 속도

### 3. 우산 / 양산 탭
- 카드 상단에 "☂️ 우산" / "🌂 양산" 탭 버튼 두 개. 기본 선택은 "우산" 탭.
- **우산 탭**: 기존 로직 그대로 — 06:00~21:00 강수확률 최댓값이 임계값(40%) 이상이면 "우산 챙기세요", 아니면 "우산 필요없어요". 배경은 실제 날씨 카테고리(맑음/흐림/비/눈) 그대로.
- **양산 탭**: Open-Meteo hourly에 `uv_index` 파라미터를 추가로 요청. 같은 06:00~21:00 윈도우에서 UV 지수 최댓값이 임계값 **6** 이상(세계보건기구 기준 "높음" 등급)이면 "양산 챙기세요" + **맑음 장면** 표시, 6 미만이면 "양산 필요없어요" + **흐림 장면** 표시. (양산 탭은 실제 날씨 카테고리가 아니라 UV 판정 결과에 따라 맑음/흐림 장면 중 하나만 골라 보여준다 — 비/눈 장면은 양산 탭에 쓰지 않는다.)
- 탭 전환은 페이지 새로고침 없이 JS로 두 결과 패널을 보이기/숨기기 하는 방식.
- 우산 판단에 쓰이는 `THRESHOLD_PERCENT`/`WINDOW_START_HOUR`/`WINDOW_END_HOUR`와 마찬가지로, UV 임계값도 코드 상단 상수(`UV_THRESHOLD`)로 분리해 조정 가능하게 한다.

### 4. 카드 안 정보 순서
위에서부터 아래로:
1. 우산/양산 탭 버튼
2. 우산/양산 문구 + 아이콘 (텍스트 레이어, 애니메이션 위)
3. 오늘 기온(최고/최저) · 강수확률(우산 탭) 또는 UV 지수(양산 탭)
4. 습도 · 바람 세기 (Open-Meteo hourly의 `relative_humidity_2m`, `wind_speed_10m`에서 현재 시각 값 추출 — 기존 `getCurrentWeatherCode`와 동일한 "현재 시각에 해당하는 인덱스 찾기" 패턴 재사용)
5. 날씨별 한줄 코멘트 (카테고리별로 미리 정의된 문구 목록에서 선택해 표시. 예: 비 → "우산 깜빡하지 마세요!", 맑음 → "나들이하기 좋은 날씨예요")
6. **카드 하단에 고정**: 시간대별 미니 타임라인 — 06, 09, 12, 15, 18, 21시(3시간 간격, 총 6개 지점)를 이모지 스트립으로 표시(예: ☀️☀️⛅🌧️🌧️☀️). 매시간 전부가 아니라 이 6개 지점만 샘플링해 카드 폭에 맞춘다. 각 지점의 `weatherCodeToCategory` 결과를 이모지로 매핑(맑음→☀️, 흐림→⛅, 비→🌧️, 눈→❄️).

## 범위 밖 (Out of Scope)

- Canvas/WebGL 기반 파티클 렌더링 (CSS 애니메이션으로 충분, 빌드 도구 없는 단일 파일 구조 유지)
- 양산 탭에 비/눈 장면 사용 (UV 판정은 맑음/흐림 장면만 사용)
- 시간대별 타임라인의 시간별(1시간 간격) 세분화 — 3시간 간격 등으로 샘플링
- 다크모드, 여러 도시, 자동 테스트 코드 (기존 v1 스펙과 동일하게 계속 제외)
- 습도/바람에 대한 별도 판단 로직(예: "바람 강하니 우산 대신 우비" 같은 추가 조건) — 단순 정보 표시만

## 기술 스택 / 구현 방식

- 기존과 동일하게 **순수 HTML/CSS/JS 단일 파일**(`index.html`), 빌드 도구 없음.
- 애니메이션은 전부 CSS `@keyframes` + `position:absolute` 파티클 요소로 구현 (비주얼 컴패니언에서 검증한 방식 그대로).
- Open-Meteo 요청에 `uv_index`, `relative_humidity_2m`, `wind_speed_10m`를 hourly 파라미터로 추가 (기존 `precipitation_probability`, `weathercode`, daily 파라미터에 이어붙임).
- 레이어링 시 흔한 실수(모든 자식이 `position:absolute`인 컨테이너가 부모 flex에서 너비 0으로 찌그러지는 문제, `position:static` 텍스트가 `position:absolute` 파티클보다 항상 아래에 그려지는 스태킹 문제)를 실제 목업에서 발견/수정했으므로, 구현 시 동일한 함정에 유의: 배경 레이어와 텍스트 레이어는 각각 명시적 `position` + `z-index`를 가진 별도 레이어로 분리하고, 레이어 컨테이너는 명시적으로 부모를 꽉 채우도록(`inset:0` 등) 만든다.

## 검증 방법

- 기존 프로젝트와 동일하게 자동 테스트 코드는 작성하지 않고, 브라우저에서 직접 열어 육안으로 확인한다.
- 확인 항목: 4가지 날씨 장면이 각각 올바르게 재생되는지, 우산/양산 탭 전환이 잘 되는지, 텍스트가 애니메이션에 가려지지 않는지, 습도/바람/코멘트/타임라인 값이 실제 API 값과 일치하는지, 카드 폭이 좁은 화면(모바일)에서도 깨지지 않는지.
